# Prompt and model benchmark (2026-10-17)

All runs go through the bridge's own `buildCommand` and `parseLine`, so they match what the extension sends. Setups ran in parallel, so times may be a little high. Times are per request, end to end.

## Test inputs (Fix mode)

1. **past tense:** `yesterday i has went to the meeting but nobody were there, can you tell me why? also the report dont have the numbers we discussed`
2. **question:** `can you explain me what is the different between let and const in javascript?` (must be fixed, not answered)
3. **tokens:** ``hey @sara_k check this https://github.com/ashahinL/localpolish/pull/3. i think the `parseLine` function have a bug 🐛 #bugfix`` (link, mention, code, emoji, hashtag must survive)
4. **mixed arabic:** `ana mesh fahem leh el meeting et2agel, بس انا هكون free بكرة after 3pm if that work for you` (each part must stay in its own script)
5. **email:** a short work email with six mistakes.

Each input runs 4 times, so 20 tries per setup. A script scores each answer (for example, "past tense" passes only with "I went", "nobody was" and "doesn't").

### After making the Fix prompt's language rule explicit

The mixed-arabic failures came from a weak "Do not translate it." The final Fix prompt spells out "Arabic stays Arabic, Franco-Arabic stays Franco-Arabic, English stays English". Re-run on the three hardest inputs, 4 runs each:

| Setup | Score | Avg | Notes |

## Things we learned

- **Long prompts break Haiku.** The first prompt had a long rule list ("keep the same words…", "if the text is already fine, return it unchanged"). Haiku often copied the text back unchanged: 6 of 12 at high effort, against 19 of 20 with a one-line task. Sonnet ignored the pull, which at first made Sonnet look like the better model. Keep prompts short.
- **Codex loads `~/.codex/AGENTS.md`.** Your personal answer format ("**Next:** … **Result:** …") ended up in the rewritten text, sometimes in Arabic. No flag turns this off (`project_doc_max_bytes=0` and `--ignore-user-config` do not). The bridge now runs Codex with its own home, `~/Library/Application Support/LocalPolish/codex-home`, which needs a one-time `codex login`. With the clean home, Luna's "question" score went from 1–4/4 to 4/4 at every effort.
- **Adaptive thinking.** On short inputs Haiku barely thinks below max. Max thinks about 3,000 tokens and takes 10 to 33 s, so it is not worth it.

## Decision (owner's call, 2026-10-17)

Arabic and mixed Arabic are not a priority. For mixed text the owner only wants spelling fixed. Cost matters more than the last few points of quality, so the defaults are the cheapest setups that score well:

- Claude CLI (default provider): `haiku`, effort `low` (19/20, the one miss was mixed Arabic).
- Codex CLI: `gpt-6-luna`, effort `none` (16/20, all four misses were mixed Arabic). Own `CODEX_HOME`.
- Grok CLI: CLI default model (`grok-4.7`), effort `low`. Slow by nature; kept as an option.
- The Fix prompt keeps the short "Do not translate it." rule, which is what scored 19/20 on Haiku low. The longer explicit language rule made Haiku high copy text back.
- Every model and effort is a user setting in the options page. These are only defaults.
