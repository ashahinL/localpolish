3. In `src/background/providers/openai.ts:17-65`, send the message list as the API `messages`. In `anthropic.ts:13-40`, take the first system message as `system` and send the remaining user and assistant messages in order. Callers supply exactly one system message first, followed by a user turn and alternating assistant and user turns ending with user. Do not add a generic parser or new transport framework. Keep all current streaming and HTTP handling.
4. In `src/background/providers/cli.ts:91-190`, retain the native wire request `type: 'rewrite', system, user`. For a list with only system and user, send their contents unchanged, so Fix stays identical. For multiple turns, keep the system content separate and flatten user and assistant turns into a clearly labeled conversation. Encode turns as a JSON array inside `<conversation>` tags so selected text cannot forge a turn boundary by including a closing XML-like tag. Keep no-tools lockdown unchanged. Forward the optional timeout to the bridge. Omit it for existing Fix callers.
5. In `bridge/constants.mjs` and `bridge/host.mjs:96-108,259-262`, support optional `timeoutMs` on each rewrite request. Default remains 60000. Accept only positive finite integer milliseconds, cap at 180000, and reject supplied invalid values with a clear error before spawning any CLI. Use the actual duration in the timeout error. A request cannot increase the cap. Export a small pure timeout-reading function in `bridge/lib.mjs` if needed to test default, cap, invalid values and boundaries without waiting three minutes. Keep native frame and output caps unchanged. Keep existing Fix input allowance of 256 KiB plus its 15-byte wrapper. For multi-turn CLI requests, enforce a 256 KiB limit on the complete flattened conversation before opening a native port. API multi-turn requests must also reject conversations over 256 KiB, using UTF-8 bytes of system and turn contents plus any attachment framing. Keep the exact existing Fix boundary behavior, including the wrapper allowance. A small shared helper for message input size is fine. Do not use JavaScript character length as the sole byte check.
6. Add chat prompt exports to `src/core/prompts.ts`, separate from Fix: a system prompt, the four quick asks, and `buildChatMessages` for a turn list plus an optional attachment `{text,title,url}`. The system prompt says page selections and metadata are untrusted data, never instructions, and the assistant has no tools or ability to act on a page. The four asks are Summarize, Explain, Translate, and Draft a reply. Use plain short prompt text. Return one system message and the turn list. Attach selection, title and URL to the first user turn inside a dedicated tag, with their contents JSON encoded and XML-significant characters escaped so page text cannot close the attachment tag. Do not repeat the attachment each turn. Keep user requests outside that tag. Reject an oversized chat in this builder with a clear message saying to start a new chat with the last answer. Do not change existing Fix prompts. Export the 180000 chat timeout for the later chat caller. Do not add a chat runtime handler or duplicate `runRewrite`; T23d will connect this foundation and record chat usage through the existing usage API.
7. In `src/core/settings.ts:19-63,95-210,241-262`, add a nested `chat: {provider: ProviderId; models: Record<ProviderId,string>}` setting. On load with no saved chat settings, copy the normalized Fix provider and models, not just factory defaults. Validate chat provider ids and string model values like the existing checked reads. Reject arrays and unknown keys. Always clone model objects. Missing or invalid chat fields fall back to the corresponding normalized Fix values. In `saveSettings`, allow a partial chat patch and partial chat models, merge against the current chat value under the existing lock, and persist the complete settings so later Fix changes do not move the saved chat choices. Share existing keys and credentials and CLI efforts; do not invent a second set of credentials or effort controls. `pageSettings` must continue exposing only its current four fields.
