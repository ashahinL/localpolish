# T19a: real local request counters
The owner confirmed they want LocalPolish usage stats, each model used and number of requests. Previously no stats existed. Build the counters; UI is a separate art-lane task.

Contract, settled for both implementers:
- src/core/usage.ts exports USAGE_STORAGE_KEY = 'usage', interface UsageRow { provider: ProviderId; model: string; requests: number }, loadUsage(): Promise<UsageRow[]>, and recordUsage(settings: Pick<Settings, 'provider' | 'models'>): Promise<void>. The Chrome local storage value for usage is the array itself. Missing/malformed data is handled as empty or bad rows ignored. Validate known provider, string model, positive safe integer count. Do not store prompts, outputs, keys, sites, URLs, dates, or per-request logs.
- Rows are keyed by provider + exact selected model string. Empty model stays empty; UI will label it Provider default. No guesses about the actual resolved model behind an alias/default.
- All-time request attempts, including failures, cancellation after start, idle requests, manual requests, retries, and Test connection. Cached answers do not count. The UI will call these Requests with a clear attempts note. No today/daily counters, token estimates, money estimates, reset/import/export.
- Only the background calls recordUsage. Serialize read/increment/write with a module Promise queue, so simultaneous requests to any model do not lose counts. Recover the queue after failure; store failure must not stop rewrites. No settings writes or full-record settings changes.

Implementation:
1. Add core usage reader/writer and behavior tests with fake Chrome storage. Test model/provider separation, concurrent increments preserve all counts, persistence across reads, missing/malformed data, failed write does not poison later writes, no settings/private text stored. Prefer a handful of strong tests, not test bloat.
2. src/background/rewrite.ts runRewrite is the single common execution path, including testConnection. Count once just before invoking stream, AFTER an already-aborted request check. If cancellation occurs while the counter save is pending, check signal again before stream, so no already-cancelled provider can hang. A counted started attempt may be cancelled during the save; document this simple definition. Await the count write but swallow its error so rewrite still runs. Keep the timeout measured from actual provider start, and avoid orphan abort listeners. Do not count bridge-status/ping or blocked/invalid messages rejected before runRewrite.

Add assertions that successful/failing rewrite and Test connection record once and an already-aborted request does not record. Ensure cancellation and timeout tests remain valid.
