## Runtime and contracts

Enforce the whole input size before usage or a provider call. Stream raw Markdown and enforce the existing 1 MiB UTF-8 output cap. Handle split surrogate pairs correctly as `runRewrite` does. Catch failures consistently with Fix, including bridge-missing errors. Keep `runRewrite` behavior unchanged. A small shared byte-budget helper is okay if needed by both, but avoid a broad rewrite or a new generic streaming framework.
3. In `src/entrypoints/background.ts`, register the chat port before the existing test and rewrite port branches. Allow only an extension-page sender URL from this extension; reject a content script sender. Validate the external request shape, require alternating user/assistant turns starting and ending with user, and validate attachment string fields. Build the system prompt in the background. Use an AbortController per port, allow one request, cancel on disconnect, and ignore duplicate starts. Load settings in the background and check cancellation again before starting a provider. The panel connects once per turn and disconnects on completion, cancellation, navigation, and unmount. Do not trust unvalidated cross-process messages in either direction.
4. Declare a side panel entry in the generated manifest and the required `sidePanel` permission. WXT may infer the path from the entry point; inspect its built manifest. Do not add `contextMenus` or entry-point commands yet. Keep 1.3.0 as the version.
5. Prepare attachment delivery for T23e using `chrome.storage.session` under `chat-pending`. Its payload is `{sequence: string, tabId: number, attachment?: {text,title,url}}`. Read it once at panel startup and follow storage changes. A fresh sequence starts a new chat and cancels any running turn. An absent attachment means a plain chat. Keep the associated tabId in panel state for T23f insertion. No pending entry is sent to an AI until the user asks. Do not store credentials in session storage or expose it to content scripts.
